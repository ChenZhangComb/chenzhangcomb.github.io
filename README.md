# Chen Zhang · 中英双语科研主页

已填入：Chen Zhang / 南开大学（Nankai University）/ 组合数学（Combinatorics）。论文、项目、学历、职称和联系方式尚未填写，可在编辑器中补充。没有使用虚构的科研成果。

## 先在电脑上使用

1. 解压文件包，保留完整文件夹结构。
2. 双击 `index.html` 查看主页；右上角 **中文 / EN** 切换语言。
3. 双击 `editor.html` 打开表单编辑器，无需安装软件或登录 GitHub。
4. 在「正在编辑」中选择中文或英文。**内容同步默认开启**：修改任一语言的字段，另一语言的对应字段会立即变成相同文字，不进行翻译。新增、删除和上移条目也同步。需要分别填写中英文时，点击「暂停同步」。邮箱、头像、学术链接和简历链接一直共用。
5. 填写基本信息，按需添加研究方向、论文、项目和经历。项目与经历为空时不会显示；论文为空时显示待更新提示。
6. 在「文件库」建立文件夹或子文件夹并上传文件，也可在论文条目里直接上传 PDF、数据或其他附件。具体操作见下方「文件库与论文附件」。
7. 点击 **下载完整网站包**，将 ZIP 解压到一个新文件夹。这个文件夹包含最新文字、附件和编辑器，双击其中的 `index.html` 查看主页，双击 `editor.html` 继续编辑。
8. 如果只改文字，且所引用的附件已经保存在网站目录或已发布到 GitHub，也可点击 **仅下载文字更新**，用下载的 `profile.js` 替换原来的同名文件。若浏览器添加了 `(1)` 等后缀，先改回 `profile.js`。新上传附件后应下载完整网站包。

编辑器会尝试在当前浏览器中保存文字草稿和文件库，不会改写磁盘文件，也不会自动上传到 GitHub。关闭页面前、更换浏览器或电脑前，请下载完整网站包；清理浏览器数据可能删除草稿和附件。浏览器不允许持久保存或存储空间不足时会显示提示，此时请在关闭页面前完成下载。

「下载文字备份」生成的 JSON **只包含文字和文件引用，不包含文件内容**；「导入文字备份」也不会恢复附件。包含附件的备份请使用完整 ZIP，解压后直接打开其中的编辑器。每种语言的每个栏目最多 500 条，JSON 文字备份最多 2 MB。

## 文件库与论文附件

1. 打开编辑器的 **文件库** 栏目，填写名称并点击「建立文件夹」。进入文件夹后可继续建立子文件夹，最多 8 层；「上一级」返回父目录。
2. 在目标文件夹点击「上传文件」，可一次选择多个文件。同名文件会自动添加编号，原文件不会被覆盖。**编辑器不设单文件大小或文件库总量上限**；实际可用容量仍取决于浏览器存储配额、设备剩余空间和内存。1 MiB = 1,048,576 字节，页面中简写为 MB。
3. 文件库会显示每个文件的网站路径。上传头像或简历后，复制这条路径到「基本信息」中的头像地址或简历地址；其他链接字段也可使用文件库路径。
4. 在 **论文** 条目下选择保存文件夹，再点击「上传论文 PDF」，上传后会自动填入该条目的论文链接。点击「上传数据 / 附件」可添加 CSV、Excel、ZIP 等文件；也可从已有文件库选择文件并点击「添加到论文」。主页会显示附件下载链接。
5. 「移除关联」只取消论文与附件的关联，文件仍保留在文件库。删除文件会先确认，并清理两种语言中对该文件的相关引用；文件夹须清空文件和子文件夹后才能删除。
6. 完成后点击 **下载完整网站包**。仅在编辑器上传成功表示文件已加入本地文件库；要让访问者下载附件，仍需把解压后的网站目录完整发布到 GitHub。

完整网站包目前使用普通 ZIP 格式：单包（包含原文件、恢复数据及目录记录）须小于 4 GiB，条目数须少于 65,535；超出格式范围时会提示，文件库中的原文件不会被删除，可逐个下载或改用外部数据链接。这是打包格式边界，不是文件库的上传大小上限。浏览器内存不足可能更早导致大文件打包失败。

论文 PDF 链接和数据附件关联也遵循内容同步开关：开启时复制到另一语言，暂停时可分别设置。体积较大的数据集可填写已有的完整 `https://...` 数据下载链接；本编辑器不提供外部文件托管或上传服务。

**从旧版迁移手动放置的文件**：如果原网站使用 `./assets/avatar.jpg`、`./assets/cv.pdf` 或其他手动加入的本地资产，请先将原文件上传到文件库，再把对应链接改为文件库显示的新路径。完整 ZIP 会检查本地引用；无法打包的引用会阻止导出，请按提示补齐或更新。确认新网站包里的文件与链接正常后，再替换旧目录。

## 内容同步的使用方式

- **只填一次**：保持同步开启，在中文或英文界面填写即可。同步原样复制文字，例如填写英文论文标题后，两种页面都会显示该英文标题。
- **分别修改中英文**：暂停同步后进行修改。再次开启时，已有的不同内容不会立即被覆盖；之后编辑的字段才会同步。
- **整体对齐**：「用当前语言内容覆盖另一语言」会复制全部个人信息、栏目条目及顺序，操作前会弹出确认。请先下载备份再替换有价值的独立内容。
- **旧版数据**：旧版两种语言中数量相同的栏目，会按现有顺序建立对应关系；数量不同时保留独立条目，避免误覆盖。需要完全对齐时，可使用整体覆盖功能。
- **离线使用**：同步在当前浏览器中完成，无需账号、翻译服务或网络连接。同步开关会在当前浏览器中记住。

如果替换了网站文件后，编辑器仍显示旧文字草稿，点击「重新载入网站文字」。本地直接打开 HTML 时，浏览器可能限制持久保存；请以下载到电脑上的完整网站包作为包含附件的备份。

## 以后发布到 GitHub Pages

你现在不需要 GitHub 账号。注册后，可按以下步骤发布：

1. 在 GitHub 新建一个公开仓库，命名为 `你的用户名.github.io`。例如，用户名为 `example`，则仓库名为 `example.github.io`。这里的 `example` 仅为示例。
2. 在编辑器下载完整网站包并解压，将解压文件夹**里面的全部文件和目录**上传到仓库根目录，确保 `index.html` 在根目录。不要只上传 ZIP，也不要额外套一层文件夹。保留 `.nojekyll`、`assets/uploads/`、`files.js`、`file-data/` 和其他随附文件；文件夹层级及文件名必须保持原样。空文件夹中的 `.gitkeep` 也应保留。
3. 打开仓库 **Settings → Pages → Build and deployment**。
4. 在 **Source** 选择 **Deploy from a branch**，选择 **main** 分支与 **/(root)**，点击 **Save**。
5. 部署完成后点击 **Visit site**。个人站点地址为 `https://你的用户名.github.io/`。
6. 日后添加、删除或修改附件时，重新下载完整网站包，将解压后的文件按相同目录结构更新到仓库；如果要从已发布仓库彻底移除旧附件，还需删除仓库中对应的旧文件。只有文字变化时，可仅替换 `profile.js`。提交更改后 GitHub Pages 会重新部署，更新可能需要几分钟。

编辑器取消大小上限不代表 GitHub 也取消限制：GitHub 网页单文件上传上限为 25 MiB，一次最多上传 100 个文件；普通 Git 仓库拒绝超过 100 MiB 的文件，Pages 发布后的整站上限为 1 GB。导出包包含附件原文件及其恢复数据，恢复数据约为原文件的 4/3，需一并计算容量；即使原文件可上传，恢复数据文件也可能超过平台上限。大数据集可放在外部存储中，再将下载链接填入论文条目。参见 [GitHub 文件上传限制](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)、[大文件限制](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github) 与 [Pages 使用限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)。

也可以使用普通仓库名（例如 `research-homepage`）；相应网址为 `https://你的用户名.github.io/research-homepage/`。本项目使用相对资源路径，同时兼容这两种地址。

GitHub 官方说明：[创建站点](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site) · [配置发布来源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) · [个人站点与项目站点](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

## 其他设置

- **头像**：上传到文件库并填写其网站路径，或使用完整图片网址。留空时显示姓名首字母。
- **简历**：上传到文件库并填写其网站路径，或使用完整 PDF 网址。
- **链接**：外部地址使用完整的 `https://...` 网址；本地附件使用文件库提供的路径。请保留路径中的大小写和编码，不要手动改名或移动导出后的附件。
- **引用**：在论文条目的 BibTeX 字段中粘贴引用，主页中会出现可展开的 BibTeX 按钮。
- **语言**：访问者的选择只记在自己的浏览器中。也可通过 `index.html?lang=en` 或 `index.html?lang=zh` 指定语言。
- **编辑权限**：公开的编辑器只是本地草稿工具，访客的修改不会影响你的主页。只有有权提交仓库文件的人才能更新已发布内容。

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `index.html` | 主页入口 |
| `profile.js` | 所有中英文内容、论文附件引用和条目对应关系 |
| `editor.html`、`editor.js`、`editor.css` | 可视化表单编辑器 |
| `sync.js` | 中英文内容同步 |
| `files-store.js`、`files-ui.js` | 文件库、附件管理与完整 ZIP 导出 |
| `files.js` | 网站随附的文件目录索引 |
| `site-source.js` | 完整网站包导出所需的页面与程序资源 |
| `app.js`、`styles.css` | 主页显示逻辑与样式 |
| `assets/uploads/` | 发布后供访问者下载或查看的附件原文件 |
| `file-data/` | 编辑器恢复随附附件所需的数据；请勿删除 |
| `.nojekyll` | GitHub Pages 纯静态发布标记 |

请保留完整目录，尤其不要删除 `file-data/` 或 `site-source.js`。即使公开主页仍能显示，缺少这些文件也可能使解压后重新编辑或再次导出失败。

页面没有外部字体、统计追踪或第三方脚本依赖。内容同步原样复制字段，不进行自动翻译。主页与编辑器都支持手机布局。所有源文件均可编辑。
